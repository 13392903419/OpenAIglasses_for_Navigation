## 二、语音与地图能否联动？

**可以联动**，但需要补齐以下环节：

1. **语音 → 后端**：ASR 已把文本送到 `start_ai_with_text_custom`，可解析「导航到松江印象城」并提取目的地。
2. **后端 → 地图**：需新增 HTTP/WebSocket 接口，供前端调用路线规划、获取当前指引。
3. **地图 → 后端**：需前端定时上报 GPS 坐标到后端，或后端提供接口供前端轮询。
4. **后端 → TTS**：已有 `play_voice_text()`，只需按优先级合并地图指引、障碍物、盲道三类文本即可。

## 四、百度 vs 高德 API 推荐

### 您已使用百度地图，建议继续用百度

| 对比项 | 百度 | 高德 |
|--------|------|------|
| 步行路线规划 | `BMap.WalkingRoute`，支持 `onSearchComplete` 获取步骤 | `AMap.Walking`，类似 |
| 实时定位 | `BMap.Geolocation.watchPosition` | `AMap.Geolocation.watch` |
| 坐标转换 | `BMap.Convertor`（WGS84↔BD09） | 自带 |
| 您当前集成 | 已用百度 AK、定位、搜索 | 需重写前端 |

**推荐**：沿用百度地图，补齐 `WalkingRoute` 路线规划与后端对接即可。若未来有跨平台需求，可再评估高德。

## 五、分步实现指南

### 第一步：语音「启动导航」+「导航到xxx」解析

**文件**：`app_main.py` 的 `start_ai_with_text_custom`

1. 增加「启动导航」关键词（与「开始导航」等效）：
   ```python
   # 在 "开始导航" 判断处增加
   if "启动导航" in user_text or "开始导航" in user_text or "盲道导航" in user_text or "帮我导航" in user_text:
   ```

2. 增加「导航到xxx」解析，提取目的地：
   ```python
   # 正则：导航到/去/到 + 目的地
   nav_to_pattern = r"(?:请帮我)?(?:导航到|导航去|去|到)\s*(.+?)(?:。|！|？|$)"
   match = re.search(nav_to_pattern, user_text)
   if match:
       destination = match.group(1).strip()  # 如 "松江印象城"
       # 调用后端接口设置目的地，触发路线规划
   ```

3. 新增全局变量与接口：
   - `current_destination: Optional[str]`：当前目的地
   - `POST /api/navigation/start`：`{"destination": "松江印象城"}` → 设置目的地并通知前端

### 第二步：百度地图路线规划与后端打通

**文件**：`templates/index.html`、新建 `app_main.py` 路由

1. **实现 `planRoute()`**（使用 `BMap.WalkingRoute`）：
   ```javascript
   function planRoute() {
     if (!currentPosition || !destinationPoint) return;
     var walk = new BMap.WalkingRoute(map, {
       onSearchComplete: function(results) {
         if (walk.getStatus() === BMAP_STATUS_SUCCESS) {
           var plan = results.getPlan(0);
           var route = plan.getRoute(0);
           var steps = [];
           for (var i = 0; i < route.getNumSteps(); i++) {
             var step = route.getStep(i);
             steps.push(step.getDescription());  // 如 "向左转进店铺街"
           }
           // 通过 WebSocket 或 fetch 发送到后端
           fetch('/api/navigation/route', {
             method: 'POST',
             body: JSON.stringify({ steps: steps })
           });
         }
       }
     });
     walk.search(currentPosition, destinationPoint);
   }
   ```

2. **实现 `startNavigation()`**：
   - 开启 `BMap.Geolocation.watchPosition` 定时上报坐标
   - 每 3–5 秒 `POST /api/navigation/position` 上报 `{lng, lat}`
   - 后端根据当前坐标与路线步骤，计算「当前应播报的指引」

3. **后端新增接口**：
   - `POST /api/navigation/start`：接收目的地，触发前端 `searchDestination` + `planRoute`
   - `POST /api/navigation/route`：接收路线步骤，存入内存/Redis
   - `POST /api/navigation/position`：接收坐标，计算当前步骤，返回 `current_instruction`

---

### 第三步：三级优先级播报融合

**文件**：`navigation_master.py` 或新建 `voice_priority_merger.py`

当前 `workflow_blindpath` 已有优先级：障碍物(100) > 转向(50) > 直行(10)。

需要扩展为：

| 优先级 | 来源 | 示例 | 实现方式 |
|--------|------|------|----------|
| **P1 紧急** | 百度地图路线指引 | 「向左转进店铺街」 | 从后端 `current_instruction` 获取 |
| **P2 导航** | 障碍物检测 | 「前方1米有障碍物，请停止」 | 已有，保持 |
| **P3 盲道** | 盲道检测+位置 | 「右前方10米发现盲道」 | 需补充「连续5秒」逻辑 |

**融合逻辑**（在 `orchestrator.process_frame` 或 `workflow_blindpath` 中）：
```python
# 伪代码
if map_instruction:      # 有地图指引
    say(map_instruction)
elif obstacle_warning:   # 有障碍物
    say(obstacle_warning)
elif blind_path_hint:    # 盲道连续5秒
    say(blind_path_hint)
```

### 第四步：盲道「连续5秒」提示

**文件**：`workflow_blindpath.py` 或 `crosswalk_awareness.py`

需求：盲道在视野主要区域连续出现 5 秒 → 播报「正前方/右侧/左侧有盲道」。

实现思路：
1. 在 `BlindPathNavigator` 中增加 `blind_path_visible_frames` 计数。
2. 若盲道 mask 中心在画面中间 40%–60% 宽度内，且面积 > 某阈值，则 `blind_path_visible_frames += 1`，否则置 0。
3. 当 `blind_path_visible_frames >= 150`（约 5 秒 @ 30fps）时，根据 `center_x_ratio` 判断左/中/右，播报一次，并重置计数，冷却 10 秒再允许下次播报。

## 七、其他需注意的改动

1. **百度 AK 配置**：从 `index.html` 移到 `.env`，通过后端 `/api/config` 下发，避免暴露。
2. **坐标系统**：百度用 BD09，GPS 为 WGS84，需用 `BMap.Convertor` 转换。
3. **室内场景**：GPS 在室内不准，可考虑「地图指引 + 视觉盲道」混合模式，GPS 失效时仅依赖视觉。
